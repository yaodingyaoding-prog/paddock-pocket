# 游客与分享发布方案

## 已确定的方向

- 产品名称继续使用“围场口袋 / Paddock Pocket”，域名、账号、Android 包名和签名保持现状。
- 第一批目标用户是中文 F1 车迷，宣传聚焦“看赛程、查天气、找回放”。
- 赛事只读内容允许游客访问；账号、头像和密码恢复仍保持原有身份校验。`AUTH_MODE=required` 保留，不通过关闭账号系统实现游客浏览。
- 赛程页和领奖台各有一个分享入口；海报在设备本地按需生成，不上传私人信息或增加追踪服务。
- 先按小规模、零付费推广运营；优先保证手机访问和分享稳定，沿用现有数据缓存及明确的过期回退。
- 外部内容发布由维护者决定。本次提供宣传材料，不代替维护者向社群发消息。

## 决策与取舍

| 决策 | 采用方式 | 原因 |
| --- | --- | --- |
| 游客访问 | 明确列出赛事 GET / HEAD 路由 | 避免把所有未来接口或写入操作一并放开；私有头像仍由服务端验证本人身份 |
| 账号服务故障 | 公共浏览继续，私有操作失败关闭 | 新访客不必先依赖账号服务；不因故障放开私人数据 |
| 海报 | Canvas PNG + 本地 QR 编码，按需加载 | 不需要付费服务或图片上传，保留系统分享与保存图片回退 |
| 分享阵容 | 仅包含最多三个车手 ID 和赛季的预览链接 | 不含邮箱、用户 ID、私有头像，不写入接收者关注 |
| 天气 | 仅使用六小时内、匹配正赛时间的预报缓存 | 无数据、已结束或超范围时不给出猜测温度，保留来源与获取时间 |
| 网站介绍 | `/about`，主站继续直接显示赛程 | 支持宣传和搜索入口，又不额外增加一次进入应用的点击 |
| 用户反馈 | GitHub Issues 与小规模人工收集 | 暂不安装统计 SDK，不收集额外用户行为或配置费用 |

### 约 20 秒演示脚本

1. 0–5 秒：打开赛程，展示比赛周末与北京时间场次。
2. 5–10 秒：切换比赛预报与当地此刻，保留时间与来源标注。
3. 10–14 秒：进入赛事回放，选择分站和平台搜索入口。
4. 14–18 秒：生成比赛周末海报或个人领奖台。
5. 18–20 秒：展示网址与“免费开源，游客即可浏览”。

先邀请少量真实车迷体验，收集“能否找到下一场、有没有回访、是否愿意分享”的反馈。暂不宣称未经测量的用户规模、实时延迟、官方授权或独家直播能力。

## 验收

自动检查覆盖公开读取、未知路由与写入方法仍关闭、头像所有权、邮件恢复授权，以及分享链接、时区、天气有效期和私人字段排除。另以浏览器检查游客入口、海报实际生成、移动布局与介绍页；系统分享目标由设备支持情况决定。
