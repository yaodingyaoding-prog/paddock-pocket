# 账号系统设计记录

更新日期：2026-10-22。状态：免费账号方案已实现并部署，正式站已启用强制登录；手机实际网络验收进行中。

## 已确认的需求

- 网站改为强制登录，注册并登录后才能使用；网页和业务数据接口均校验会话。
- 使用邮箱与密码，提供注册、邮箱验证、登录、找回密码及退出。
- 开放注册，不使用邀请码。
- 适配手机、平板和电脑，支持保持登录；服务异常时显示可重试状态。
- 仅收集必要账号信息，密码不明文保存；账号服务不依赖维护者的个人电脑持续开机。
- 首版按数百名用户规划；不加入收费会员、社交登录和收藏同步。

上述范围由用户在需求确认阶段接受。随后用户要求“哪个不要钱用哪个”，授权按零付费约束选择服务；因此选择方案 B 的免费套餐。用户随后回复“可以”，接受深色背景、青绿色按钮、桌面双栏 / 手机单列，以及免费额度和低活跃暂停的取舍，并已自行创建服务商账号及 Supabase 项目。

## 当前工程与交付目标

- 正式工程为本仓库，部署于 `https://f1.xiaodinglab.com/`，运行环境为 Cloudflare Workers、Vinext、React。
- 已配置 Supabase Auth 与 Resend SMTP，并在本机通过真实邮箱注册、验证、登录和密码恢复；正式站运行时配置已完成并启用登录。偏好保存在设备浏览器中。
- 本次账号方案以独立域名正式站为目标；历史 Sites 预览站和独立 Android 原生工程不视为自动同步完成。
- 在验证真实邮箱发送、账户恢复和接口鉴权之前，不启用线上强制登录。

## 方案比较与选择

### A：Better Auth + Cloudflare D1 + 事务邮件服务（本轮不选）

- 使用现有 Cloudflare 环境承载认证，D1 存储账号、会话及验证记录。
- Better Auth 提供邮箱密码认证与会话流程；使用现成认证库，不自行发明密码算法。
- 注册验证及找回密码通过独立邮件服务发送，候选为 Resend。
- 账号接口使用本站域名，便于统一界面、会话及后续用户功能。
- 项目负责认证库升级、数据库迁移、邮件配置、备份及运行检查。
- 技术验证点：Vinext 与 Worker 的集成、D1 迁移、密码哈希的 CPU / 内存成本、会话和请求限制策略。

Better Auth 已提供原生 D1 支持与邮箱密码认证，但这不等于本项目集成已验证。Workers Free 每次调用的 CPU 配额为 10ms，默认 scrypt 哈希是否适用须实测；不能通过削弱密码保护来追求免费。必要时评估 Workers Paid，目前基础订阅为每月 5 美元，另按使用量计费；未授权订购。

### B：Supabase Auth Free + Resend Free（按零付费约束选用）

- 使用托管账号服务，减少项目内认证和会话管理的实现工作。
- 需要额外的 Supabase 项目，并维护与现有 Cloudflare 应用之间的服务端鉴权集成。
- 正式公开注册仍需配置自有发信服务；内置 SMTP 仅面向预授权测试收件人，不适合正式开放注册。
- 需要验证新增服务链路在目标用户网络中的实际表现，不能假定与现有网站相同。
- Supabase Free 当前包含每月 50,000 活跃用户、500MB 数据库和 5GB 出站流量；这些是分别计算的额度，不代表全部业务无限量。
- 免费项目在连续一周不活跃后可能暂停；暂停时无法正常认证，需要维护者在后台恢复。首版不承诺付费服务等级的可用性，不安排虚假访问规避暂停规则。

## 零付费约束与免费额度

- 只选择 Supabase Free 与 Resend Free；不升级付费套餐、不购买附加项、不启用邮件按量超额扣费。
- 额度用尽时可能导致注册、发信或账号访问受限；显示相应说明并由维护者处理，不擅自付费或绕过平台额度。
- Resend 当前免费额度为每月 3,000 封、每天 100 封；邮件数量不等于注册用户数，重发和找回密码也占用额度。
- 发信域名为 `auth.xiaodinglab.com`，DKIM 与两条 CNAME 已通过 Resend 验证；只开启发信。
- 不承诺 QQ、163、iCloud 等邮箱的收件速度，正式启用前实测注册验证和密码找回。

## 已接受的页面与流程设计

- 视觉沿用围场口袋品牌：深色底、青绿色主按钮和简洁赛道线条，使用本地字体及轻量装饰，避免登录前下载完整赛事应用和大型模型。
- 桌面采用左侧品牌介绍、右侧登录表单；手机和平板窄屏采用居中单列表单，兼容软键盘、密码管理器和 Safari 自动填充。
- 登录表单提供邮箱、密码、显示 / 隐藏密码、保持登录、忘记密码、登录按钮及注册入口，不提供游客进入。
- 注册页提供昵称、邮箱、密码和确认密码，提交后进入待验证页面，支持带冷却时间的重发验证邮件及修改邮箱。
- 邮箱验证完成后返回本站提示成功并进入登录流程；失败、过期或重复使用链接时提供重新发送入口。
- 找回密码页只收集邮箱并显示不泄露账号存在性的提交结果；邮件链接进入本站设置新密码页面。
- 按产品要求，密码长度不少于 6 位，允许长密码、粘贴和浏览器生成密码；实际可用上限与 Supabase 设置核对后确定。
- 登录成功恢复用户原本访问的本站页面；回跳地址仅接受本站允许的路径，不接受任意外站地址。
- 设置页增加账号摘要和退出入口，网站偏好仍按本机保存；不顺带增加收藏同步等未确认功能。

## 集成与运维设计

- 页面通过本站账号接口访问 Supabase，密码校验由 Supabase Auth 执行；保持现有 Cloudflare 免费部署，不在 Worker 内执行密码哈希。
- 会话使用由服务端管理的 HttpOnly Cookie，正式环境开启 Secure 与合适的 SameSite 策略；登录凭据不写入浏览器 localStorage。
- 认证接口与业务接口统一处理会话有效性、邮箱验证状态、刷新和错误提示。私有响应不进入共享缓存，令牌不出现在日志或公开代码中。
- 公共路径仅包含登录、注册、验证 / 找回流程、隐私说明及必要静态资源；受保护业务接口在匿名状态返回 401。
- 对注册、登录、重发及找回请求实施频率限制；区分平台不可用与凭据错误，服务故障时不开放匿名访问。
- 事务邮件经 Supabase 的自定义 SMTP 接入 Resend，发信地址为 `no-reply@auth.xiaodinglab.com`；正式邮件链接指向 `f1.xiaodinglab.com`，本机验收暂用已批准的 loopback 回跳地址。
- 由维护者持有 Supabase 与 Resend 账号。发信密钥及服务端会话密钥仅配置在服务端；不要求在聊天中发送密码或管理员令牌。
- 项目账号只用于围场口袋，不需要访客登录 ChatGPT、Cloudflare、Supabase 或 Resend；后两者是维护者配置的平台。
- 设置错误或平台暂停时显示暂时无法登录及重试入口；已有用户的退出与会话恢复按实际错误状态处理，不谎称持续可用。
- 手动备份必要的项目配置和非敏感运营数据；确认平台免费版的导出范围后制定账号数据恢复步骤，不宣称已具有完整免费灾备。

## 后端实施评估

- 架构契合度 5、可测试性 5、业务复杂度 2、数据风险 1、运维风险 3；BFRI = (5 + 5) - (2 + 1 + 3) = 4，按中等风险增加服务与接口集成检查。
- 使用 routes → controller → service → repository 分层，参数由 Zod 校验，配置集中于 `unifiedAuthConfig`。
- 密码计算交由托管 Supabase Auth，应用不实现密码算法、不访问其管理 API；认证与上线开关隔离。
- 按零付费和最少外部服务约束，使用已有 Cloudflare Workers 可观测性及集中脱敏错误日志，不另建 Sentry 账号或传输账号资料至新的监控服务。
